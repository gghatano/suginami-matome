# これまでの判断と失敗

このリポジトリで過去に決めたこと、起きた失敗と、その理由の記録です。同じ失敗を繰り返さないため、また「なぜこうなっているのか」に答えるために残しています。新しい判断をしたら、いちばん上に足してください。

書き方：**何が起きた／何を決めた → なぜ → どうした → 今の決まり**

---

## 2026-11 開発者ドキュメントを Diátaxis で整理

- **決めたこと**：ドキュメントを、チュートリアル・ハウツー・リファレンス・解説の4種類に分けた。用語集と、この記録を足した
- **なぜ**：1つのファイルに手順・仕様・理由が混ざっていて、「児童館を増やしたい」ときに読むべき部分を探す必要があった。初めての人には特に読みにくかった
- **今の決まり**：[ドキュメントを書く](../howto/write-docs.md)

## 2026-11 GitHub Pages を develop の確認環境に戻し、ドキュメントの公開先にした

- **起きたこと**：GitHub Pages が2か月ほど古いままだった
- **なぜ**：Pages は `develop` への push でだけ更新される設定だったが、`develop` が消えていた（`develop` → `main` のマージで「Delete branch」を押したと思われる）
- **どうした**：`develop` を作り直した。Pages は「`develop` のコード + `main` のデータ」を配信するようにした（データは `main` にしか入らないため）。`develop` からの公開を Environments で許可した
- **今の決まり**：`develop` は消さない（Rules で削除を禁止する）。[本番に出す](../howto/release.md)

## 2026-11 児童館カレンダーの定期更新を「専用セッション」に移した

- **起きたこと**：定期更新が、読み取りまではできても GitHub への push が 403 で拒否され、2週続けて反映されなかった
- **なぜ**：「毎回まっさらなセッションを作る」スケジュールしたタスクには、リポジトリが紐づいておらず、push の権限がなかった
- **どうした**：このリポジトリを指定して作った専用セッションに、毎回依頼が届く形にした。あわせて月曜だけでなく木曜も実行するようにした（区のページは月末に更新されることが多く、反映を早めるため）
- **今の決まり**：[定期更新を見る・直す](../howto/weekly-update.md)。新しい自動処理は、最初に手動で一度動かして、最後（push）まで通ることを確かめる

## 2026-11 対象の月が終わったおたよりは読まない

- **起きたこと**：前の月の号が毎回「未読」として出て、定期更新がそれを丸ごと読もうとしていた
- **どうした**：リンク文字列の「○月号」で目安を付け、表紙の見出しで確かめてから「省略済み」として記録するようにした
- **今の決まり**：`register.py --skip-past`

## 2026-11 児童館カレンダーの画面がずれないようにする（4回）

同じ種類の問題が4回起きました。いずれも「中身の量で高さが決まっていた」のが原因です。

| 起きたこと | 対処 |
|---|---|
| 申込カードが0件で欄が縮み、下がずれた | 欄の高さを固定し、0件でも同じ高さの枠を出す |
| Windows でカードがはみ出したときだけ、スクロールバーの分ずれた | スクロールバーの場所を常に確保 |
| 見出し横の注記が、件数の表示が長いと2行になった | 注記を独立した1行にし、隠すときも高さを確保 |
| 施設を足したら、長い説明でカードが伸びた | 高さを「最小」でなく「固定」にし、各項目の行数を決めた |

- **今の決まり**：出たり消えたり長さが変わったりするものは、場所を先に確保する（[画面づくりの原則](ui-principles.md)）

## 2026-11 色は施設を表す（対象では分けない）

- **決めたこと**：カレンダーのチップの色は施設を表す。対象（小学生以上／乳幼児）は色で分けない
- **なぜ**：施設を増やすと、色が「施設」と「対象」の2つの意味を持ってしまう。また、小学生以上と乳幼児を同時に見る使い方はしない
- **今の決まり**：対象は「表示するイベントの設定」で切り替える

## 2026-11 おたより PDF は目で読む

- **起きたこと**：`pdftotext` でテキストを抜き出すと、ふりがなが本文に混ざって日付と時刻が崩れた
- **どうした**：ページを画像にして Claude が目で読む。最初の号は人が確かめてから登録する
- **今の決まり**：[児童館カレンダーのしくみ](jidoukan-pipeline.md)

## 2026-11 マージ後の push が取りこぼされた

- **起きたこと**：PR をマージした直後に同じブランチへ push した変更が、本番に入っていなかった（2回）
- **どうした**：最新のベースブランチから作り直し、別の PR にした
- **今の決まり**：マージ済みの PR のブランチに追加の変更を積まない
