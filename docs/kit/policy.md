# 開発者ドキュメント 方針定義書

> **持ち出し用。** ほかのリポジトリで開発者ドキュメントを作るときに、[指示書](instructions.md) と一緒にコピーして使う。このリポジトリ自身の決まりは [ドキュメントを書く](../howto/write-docs.md) にある（内容は同じ方針を、このリポジトリ向けに書いたもの）。

このリポジトリの開発者ドキュメントを、どう作り、どう保つかの決まり。人（初めて触る人を含む）と AI（Claude Code など）の両方が、同じものを読んで作業できる状態を目指す。

---

## 1. 原則

1. **原本は Markdown だけ。** 本文は `docs/*.md` にだけ書く。人向けの HTML（閲覧ページ・スライド）は Markdown を読み込んで表示するだけで、本文を持たない
2. **人と AI が同じものを読む。** AI 向けの別資料は作らない。AI の入口（`CLAUDE.md`）は短くし、`docs/` を指す
3. **読む人の目的で分ける。** Diátaxis の4種類（チュートリアル・ハウツー・リファレンス・解説）に分け、1つのファイルに種類を混ぜない
4. **初めての人を基準に書く。** 専門用語は用語集に入れ、図と表で拾い読みできるようにする
5. **「なぜ」を残す。** 決めたことと失敗は、理由と一緒に時系列で記録する
6. **コードと食い違わせない。** 仕様を変えたら、同じ PR でドキュメントも直す。食い違ったらコードが正

---

## 2. 構成

```
CLAUDE.md                 AI の入口（短く。docs/ を指し、守ることを列挙）
docs/
  README.md               入口。全体の地図・読む順番・全ドキュメントの表
  glossary.md             用語集
  slides.md               5分でわかるスライドの原本
  tutorial/               チュートリアル
  howto/                  ハウツー（よくある作業ごとに1本）
  reference/              リファレンス
  explanation/            解説
    history.md            これまでの判断と失敗（新しいものが上）
  index.html              閲覧ページ（Markdown を表示するだけ）
  slides.html             スライド表示（slides.md を表示するだけ）
```

### 4つの種類

| 種類 | 読む人の状態 | 書き方 | 書かないこと |
|---|---|---|---|
| チュートリアル | 初めてで、まず慣れたい | 1本道の手順。必ず成功するように。所要時間とゴールを先に書く | 選択肢や例外 |
| ハウツー | やりたい作業が決まっている | 手順・確認表・チェックリスト。実例を添える | 仕組みの長い説明（解説へリンク） |
| リファレンス | 正確な値を引きたい | 表で網羅。コードと一致させる | 手順や理由 |
| 解説 | 仕組みや理由を知りたい | 図と「なぜ」が中心 | 手順 |

### 最低限そろえるもの

| ファイル | 中身 |
|---|---|
| `README.md` | 何のリポジトリか（図1枚）、読み方（4種類の分岐図）、初めての人が読む順番（3本程度）、全ドキュメントの表、困ったときの行き先 |
| `glossary.md` | 初めての人がつまずく言葉。Git・GitHub の基本語も含める。関係する言葉を近くに並べる |
| チュートリアル 1本 | 手元で動かす → 小さな変更 → PR → 確認環境 → 本番、を一通り体験する |
| ハウツー | 実際によく起きる作業ごとに1本（例：「対象を1つ増やす」「本番に出す」「定期処理を直す」「ドキュメントを書く」） |
| リファレンス | ファイルとフォルダ、コマンド、データ形式、設定・URL パラメータ、環境と自動処理（公開先・定期実行・権限・困ったとき） |
| 解説 | 全体の構成、主要な仕組み、設計の原則、`history.md` |
| `slides.md` | 最初の5分で読む要点。詳しい話は各ドキュメントへのリンク |

## 3. 書き方

- **短い段落、表、箇条書き。** 拾い読みできるように
- **専門用語は用語集へ。** 初出で用語集にリンクする
- **図を使う。** 流れは Mermaid の縦向きフローチャート（`flowchart TD`）。登場人物のやりとりは `sequenceDiagram`。スマホでも読めるよう横長の図は避ける
- **パスはリポジトリからの相対で書く**（例：`scripts/fetch.py`）
- **ハウツーには実例を添える。** 実際に行った作業（PR 番号など）を例として示す
- **困ったときの表を置く。** 「症状 → よくある原因 → 対処」の3列

### Mermaid の注意

- 改行は `<br>`
- 文字に `(` `)` `[` `]` を含むときは `"..."` で囲む
- 横長になる図は `TD`（上から下）にする

### 判断と失敗の記録（`explanation/history.md`）

新しいものを先頭に足す。1件の形：

```markdown
## YYYY-MM 見出し（何が起きた／何を決めた）

- **起きたこと／決めたこと**：
- **なぜ**：
- **どうした**：
- **今の決まり**：（関係するハウツーやリファレンスへのリンク）
```

同じ種類の問題が繰り返したら、1つの項目にまとめて表にし、共通の原因と今の決まりを書く。

## 4. 人向けの HTML

### 閲覧ページ（`docs/index.html`）

- 左に目次、右に本文。スマホでは目次を横スクロールにする
- 目次は HTML 内の `DOCS` 配列から作る。`group`（案内・チュートリアル・ハウツー・リファレンス・解説）でまとめる
- `#howto/add-xxx` のようなアドレスで、そのドキュメントを開く
- Markdown は `marked`、図は `mermaid` で表示する（cdnjs から版を固定して読み込む）。**読み込めないときは Markdown の原文をそのまま出す**
- `docs/` 内の `.md` へのリンクは閲覧ページ内で開く。それ以外のファイルへのリンクは GitHub のファイル表示を開く
- 表はスマホで最低幅を持たせ、はみ出す分は表だけ横スクロール
- ライト・ダークの両方に対応。`noindex`

### スライド（`docs/slides.html`）

- 原本は `docs/slides.md`。`---` だけの行で区切る（スライド内で区切り線は使えない）
- 1枚に見出し1つと、箇条書きか表を1つ。8〜10枚
- PC は 16:9 で1枚ずつ（← → キー、クリック、`#5` で5枚目）。スマホは縦に並べてスクロール
- 中身の例：何を作っているか／データや処理の流れ／ブランチの流れ／公開先／守ること／よくある作業と手順書／ドキュメントの決まり／次に読むもの

### 公開先

- 開発用の確認環境（例：GitHub Pages）でだけ公開する。本番には出さない（配信対象から `docs/` と `CLAUDE.md` を除外する）

---

## 5. AI の入口（`CLAUDE.md`）

短く保ち、次だけを書く。

1. 応答言語の指定（冒頭に。途中経過も含めることを明記。`.claude/settings.json` の `language` も併用）
2. リポジトリの1行説明
3. 「作業の前に `docs/` を読むこと」と、4種類それぞれの場所
4. **守ること**（ブランチの流れ、データの扱い、画面の原則、ドキュメントも一緒に直す、原本は Markdown、判断や失敗は記録する、確認のしかた など）
5. よく使うコマンド

詳しい説明は書かない。`docs/` へのリンクにする。

---

## 6. 保守のルール

- **仕様を変えたら同じ PR で直す。**
- **ドキュメントを足したら3か所をそろえる。** ① 該当フォルダに `.md` を置く ② `docs/README.md` の表に1行 ③ `docs/index.html` の `DOCS` に1行
- **判断や失敗があったら `history.md` の先頭に足す。**
- **スライドと食い違ったら、同じ PR で `slides.md` も直す。**
- **表示を確かめる。** 手元で `python -m http.server` などで配信し、閲覧ページとスライドを PC とスマホ、ライトとダークで見る

### PR のチェックリスト（ドキュメントに関わる変更）

- [ ] 仕様の変更に合わせて `docs/` を直した
- [ ] 新しいドキュメントを `README.md` の表と `index.html` の `DOCS` に足した
- [ ] 新しい用語を用語集に足した
- [ ] 判断や失敗を `history.md` に記録した
- [ ] HTML に本文を書いていない
