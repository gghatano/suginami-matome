# 開発者ドキュメント作成 指示書

> **持ち出し用。** 使い方：このファイルと [方針定義書](policy.md) を、対象のリポジトリで作業する Claude Code にそのまま渡す（貼り付ける）。`{{ }}` の部分は埋めるか、消して Claude に調べさせる。原文をコピーするときは、GitHub の `docs/kit/` にある Markdown を開いて「Raw」から写すと崩れない。

---

このリポジトリに、開発者ドキュメントを作ってください。決まりは添付の「方針定義書」に従います。食い違ったら方針定義書を優先してください。

## 前提

- リポジトリ：{{owner/repo}}
- 読む人：{{例：初めてこのリポジトリを触る開発者、Claude Code}}
- 確認環境（ドキュメントを公開する場所）：{{例：GitHub Pages / なし}}
- 本番の配信から外す方法：{{例：.assetsignore / .vercelignore / 該当なし}}
- ブランチの流れ：{{例：作業ブランチ → develop → main}}
- 応答と文書の言語：日本語

## 進め方

各段階の終わりで、私に結果を短く報告してください。段階1の終わりでは、私の確認を待ってから進んでください。

### 1. 調べて、目次を提案する（ここで一度止まる）

1. コード・設定・CI・README・既存のドキュメントを読み、全体の構成とデータや処理の流れをつかむ
2. `git log` と Issue・PR の履歴から、**実際によく起きている作業**と**過去の判断・失敗**を拾う
3. 次を提案する
   - ドキュメントの一覧（4種類それぞれに何を書くか。ハウツーは実際によくある作業から選ぶ）
   - 初めての人が読む順番（3本程度）
   - チュートリアルの題材（手元で動かす → 小さな変更 → 本番まで、が一通り体験できるもの）
   - `history.md` に載せる過去の判断・失敗の候補
   - 分からなかったこと（推測で書かずに、ここで質問する）
4. 履歴が浅く、よく起きている作業や過去の失敗がほとんど拾えないときは、その旨を報告し、最初は `README.md`・`glossary.md`・チュートリアル・`CLAUDE.md` だけに絞る案も出す（ハウツーや `history.md` を推測で埋めない）

### 2. Markdown を書く

1. 方針定義書の「構成」どおりにフォルダを作る
2. `README.md` → `glossary.md` → 解説 → リファレンス → ハウツー → チュートリアル → `history.md` の順に書く
3. 書くときの決まり
   - コードを読んで確かめたことだけを書く。分からないことは「要確認」と書いて報告する
   - 流れは Mermaid の `flowchart TD`。ほかの書き方の決まりは方針定義書の「書き方」
   - ハウツーには実例（実際の PR やコミット）とチェックリストを付ける
   - リファレンスはコードと一字一句合わせる（ファイル名、コマンド、項目名、既定値）
4. ドキュメントの書き方そのものも `docs/howto/write-docs.md` として残す（方針定義書をこのリポジトリ向けに書き直したもの）

### 3. 人向けの HTML を作る

1. `docs/index.html`（閲覧ページ）と `docs/slides.html`（スライド）を、方針定義書の「人向けの HTML」の要件で作る。**本文は HTML に書かない**
2. `docs/slides.md` を書く（8〜10枚）
3. 確認環境で `docs/` が見られるようにする。本番の配信対象からは外す

参考の実装（同じ方針で作ったもの）：
- https://github.com/gghatano/suginami-matome/tree/develop/docs
- 公開例：https://gghatano.github.io/suginami-matome/docs/ と https://gghatano.github.io/suginami-matome/docs/slides.html

### 4. AI の入口を整える

1. `CLAUDE.md` を方針定義書の「AI の入口」どおりに書く（既存があれば、短く保ったまま書き直す）
2. `.claude/settings.json` に `"language": "japanese"` を入れる（既存の設定は消さずに足す）

### 5. 確かめる

1. 手元で配信し、Playwright で次を確かめる
   - 閲覧ページ：全ドキュメントが目次から開ける。リンク切れがない。図が描かれる
   - スライド：全枚数が枠からはみ出さない。← → で送れる。`#5` で5枚目が開く
   - PC（1280×800）とスマホ（iPhone 相当）、ライトとダーク
   - 整形用ライブラリを読み込めないとき、Markdown の原文が出る
2. `docs/` 内の相対リンクがすべて実在のファイルを指すことを、スクリプトで確かめる
3. スクリーンショットを数枚、私に送る

### 6. PR にする

- 作業ブランチから、{{向け先のブランチ}} に向けて PR を作る
- PR の説明に：作ったドキュメントの一覧、確かめたこと、要確認として残したこと

## 完了の条件

- [ ] 方針定義書の「最低限そろえるもの」がそろっている
- [ ] `README.md` の表、`index.html` の `DOCS`、実在のファイルが一致している
- [ ] HTML に本文が書かれていない（本文はすべて `.md`）
- [ ] `CLAUDE.md` が短く、`docs/` を指している
